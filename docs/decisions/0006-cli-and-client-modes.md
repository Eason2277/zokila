# 决策 0006：Zokila 面向 CLI 与图形客户端

- 日期：2026-11-15
- 状态：用户确认产品目标；共享运行时与部署方式待验证
- 关联：0004 个人旅行方向、0005 产品名称

## 决定

走起啦 · Zokila 未来提供 CLI 模式和图形客户端模式，服务于同一旅行产品。两种入口应复用旅行领域能力、行程状态、来源信息、数据策略和外部操作确认规则。

## 理由

- 图形客户端面向普通旅行者，适合交互式规划和查看行程。
- CLI 提供另一种直接操作入口，可服务命令行工作流与高级用户。
- 复用应用能力可避免两个入口产生不同的 Agent 行为和安全规则。

## 未决项与风险

- CLI 是个人本地工具、远程服务客户端，还是两者兼有？
- 图形客户端最终采用 Electron、Web、移动端，或渐进式组合？
- CLI 与客户端是否共用账号、行程数据、偏好和会话？
- 本地运行有利于本地数据控制，但跨设备同步和模型凭证管理更复杂；服务端运行支持多端一致性，但增加账号、安全、留存和运维责任。
- 当前 CLI 与客户端产品能力均未实现；旧 Electron 界面仍是市场研究演示原型。

## 重新评估条件

在实现双端前，通过用户任务验证 CLI 的目标用户与必要性，并确定是否需要跨设备连续性。若 CLI 只服务开发流程，它可以是独立开发者工具；若服务同一旅行者，则必须共用核心业务模型与授权策略。
