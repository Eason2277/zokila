# 走起啦 · Zokila：产品概要

> 状态：中英文产品名称与旅行方向已由用户确定；具体用户与首个高频场景仍是待验证假设。

## 一句话

走起啦 · Zokila 帮助普通旅行者把目的地、日期、预算、兴趣和现实约束整理成可编辑、信息有来源、可以逐步确认的行程计划。

## 产品定位

面向个人用户的旅行与出行规划 Agent。产品以个人旅行决策为核心，不是企业差旅系统，也不是覆盖所有生活消费的通用助手。工程上追求企业级可靠性和安全边界。

## 首批用户假设

- 主要用户：需要自己规划旅行、但不想在多个来源间反复搜索和拼接行程的人。
- 初始场景候选：周末短途或数日自由行；具体人群、地区、同行方式尚未验证。
- 暂不限定为女性用户。女性旅行者的具体需求可以通过研究和反馈形成后续场景，不能把女性视为单一偏好群体。

## 用户问题假设

旅行计划需要同时考虑日期、预算、地点、交通、营业时间、同行人和个人兴趣。资料分散且时效性不同，手工拼接后还要反复检查路线是否可行。产品假设是 Agent 能降低整理和调整计划的成本，同时让用户理解依据并保留决定权。

## 核心流程假设

1. 用户填写目的地、日期、预算、兴趣、节奏、同行人和约束。
2. Agent 询问会实质影响计划的缺失信息，或将未确认条件记录为假设。
3. Agent 检索允许使用的地点与出行信息，生成分日行程并标注来源和更新时间。
4. 用户修改、比较替代方案，并请求局部调整。
5. 用户确认后自行预订；若未来集成预订，任何下单都必须由用户明确确认。

## 价值主张

- 少花时间在搜索、整理和路线拼接上。
- 行程能按预算、时间、兴趣和同行条件解释与修改。
- 价格、开放时间、交通等可能变化的信息标记来源与时效；不确定内容明确呈现。

## 质量与安全原则

- 不编造价格、班次、营业时间、可订状态、交通耗时或安全结论。
- 把用户偏好、来源事实、Agent 推荐和待确认项分开呈现。
- 地点、日期、同伴和偏好属于个人上下文；最小化收集，明确外部服务的数据流。
- 不未经用户确认预订、购买或联系服务提供方。
- 安全与无障碍信息保持谨慎并提供来源，不承诺绝对安全。

## 首轮成功信号

先建立实际基线，不预设目标数字：完成可用计划所需时间、用户修改次数与原因、关键地点/时间信息的来源有效性、路线冲突发现情况、用户是否愿意再次使用。

## 暂不做

- 外卖、穿搭、美妆、礼物等其他消费场景。
- 全自动预订、购买或未经确认的外部操作。
- 面向所有国家和所有旅行类型的完整覆盖。
- 社交旅行平台、复杂多人协作、企业差旅管理。

## 待验证问题

1. 哪类旅行者和旅行类型最常遇到规划负担？
2. 用户最希望自动化的是目的地发现、行程安排、交通衔接还是预算控制？
3. 哪些地点、地图、交通和价格数据源可合法、稳定地使用？
4. 用户是否愿意保存个人偏好、位置或同行信息？保存多久、如何删除？
5. 用户需要分享、协作或导出的行程格式是什么？

## 验证建议

选 3–5 个真实或脱敏旅行计划，比较用户原有做法与助手流程，记录规划时间、错误/过时信息、修改点和复用意愿。小样本用于发现工作流问题，不作为普遍效果结论。
